# 拓扑探测与三项缺陷修复计划（定稿：p1、p2 都是监听端口）

## 需求口径（锁定）

1. **边 = `A:p1 → B:p2`，p1 与 p2 一律是监听端口**（服务级依赖，如 `web-01:80 → db-01:3306`）；临时端口仅作解析中间值，**不落库、不上图**。
2. 一个 IP = 一个节点；命令只读、无任何高危/破坏性代码；探测不影响服务器性能。

## 探测命令白名单（服务器端共 3~4 个进程，全部毫秒级，一次 exec）

| 数据需求 | 命令 | 性质 |
|---|---|---|
| 网卡服务器 IP | `ip -o addr show scope global`（回退 `ifconfig -a`） | 只读 |
| socket 表（连接+inode+监听） | `cat /proc/net/tcp /proc/net/tcp6` | 纯 cat |
| 进程→socket 归属 | `find /proc/[0-9]*/fd -lname 'socket:\[*' -printf '%p %l\n'`（BusyBox 回退 `ls -l /proc/[0-9]*/fd`） | 只读，**单进程内核态遍历，替代旧的逐 fd readlink 风暴** |
| 防火墙策略 | `iptables-save`（回退 `nft list ruleset`/`ufw status`） | 只读转储，10 分钟 TTL |

## 解析管道（全部在 NexTerm 本地）

1. LISTEN 行（state=0A）→ 每服务器**监听端口集合**（排除回环）→「我开了哪些端口」。
2. find 输出 → **pid → 其打开的全部 socket inode 集合**；结合 1 → **pid → 它监听的端口集合**。
3. ESTABLISHED 行（state=01）→ 连接 inode → 归属 pid：
   - 接受方：local 端口本来就是监听端口 = **p2**；
   - 发起方：归属进程的监听端口 = **p1**；
   - 产出边 `A:p1 → B:p2`（两端监听端口，稳定不随重连变化）。
4. **降级规则（诚实展示，不编造）**：非 root 探测时其他用户进程归属不可见（内核权限限制，`ss -p` 同样受限），或发起进程不监听任何端口（如 curl）→ 该边降级为 `A → B:p2`（A 为服务器节点）。
5. 出向连接仅当对端 IP 命中已知节点才落库（不为陌生公网地址建节点）；排除回环、自连。
6. 高危代码防御：扩展现有守卫测试，静态断言命令永不包含 `rm/dd/>\/>>/tee/sed -i/chmod/chown/kill/systemctl/service/apt/yum/dnf/mkfs/mount/curl/wget` 及 `iptables -A/-I/-F/-X`、`nft add/delete/flush`、`ufw enable/allow` 等写入/变更模式。

## 展示模型

- **服务器级图**：A ↔ B 聚合边，hover/展开显示该对之间全部服务依赖（`A:p1 → B:p2` 列表）。
- **端口级图**：复用 `port-topology.tsx` 下钻 + `port-link-editor-dialog.tsx`（编辑/隐藏/删除已有）；端口节点只来自监听端口集合。
- 去重键 `(A:p1, B:p2)`；lastSeenAt 更新，连续未见的旧边淡显、可手动清理，探测永不硬删。

## 节点唯一性：IP = 节点

- observed 节点 id 按规范化 IP 全局唯一（不再含分组）；启动迁移合并同 IP 重复节点（边重定向，位置/标签保留）。
- 多网卡多 IP = 一个节点；remote_ip 命中已知节点 IP 集合 → 归该节点。
