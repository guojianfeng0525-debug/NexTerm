## 3. 优先级终裁（竞品差距 × 批次对齐）

| 竞品 P0 差距 | 对齐批次 | 说明 |
|---|---|---|
| MySQL provider | B27 | 与 master plan 一致；因成本高于导入导出/备份，置于其后 |
| 导入/导出向导 | B25 | **提前于 master plan 的 B26 位置**（PG 用户已在用，PG 生态高频刚需 > MySQL 长期工程） |
| 备份/恢复 | B26 | 同上提前 |
| 查询历史 + snippet | B28 | 低成本高感知，可作独立小批插入 M3 任意间隙 |
| 可视化执行计划 | B29 | PG 先行，DBA 刚需 |

> 相比 master plan 原始 M3 顺序（B25 MySQL → B26 导入导出 → B27 备份恢复）的调整：**导入导出/备份恢复提前，MySQL 后置**。理由：PG 用户为当前主力（MySQL 仅实验性），导入导出/备份是 PG 生态每日高频；MySQL 完整 provider 是长期工程（SSH/TLS/编辑/explain 全链路），置于其后再推进不损失节奏。**✅ 用户已确认此顺序（2026-08-27）**。
