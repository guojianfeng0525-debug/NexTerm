# 网络拓扑与网络诊断 — 架构设计

> 当前契约：**只读本机、零安装、零主动访问**。
> 网络拓扑不会从 A 服务器连接 B 服务器的任何 IP、端口或地址，也不会从本机发起连通性测试。

---

## 1. 不可违反的安全边界

1. **手动触发**：只有用户点击「探测当前服务器」才会执行采集；挂载、切换服务器、启动应用、打开端口详情都不得触发。
2. **只读当前 SSH 服务器**：命令只读取该服务器本机状态，不扫描网段、不做邻居发现、不解析 DNS、不连接 observed IP。
3. **零主动网络路径**：网络拓扑没有 TCP/UDP/ICMP/DNS/ARP/traceroute/端口扫描命令，也没有 `nc`、`/dev/tcp`、`direct-tcpip` 或其它 fallback。
4. **零安装**：Linux socket 数据限量读取 `/proc`；接口只使用系统自带命令。缺失时按段降级，不安装工具。
5. **不保存凭据**：`net_*` 表不得出现 password / privateKey / passphrase / token。节点只按 `connectionId` 引用已保存连接。
6. **自动 / 人工字段分离**：重新采集只允许覆盖白名单中的自动字段，人工备注、标签、布局和隐藏状态必须保留。
7. **负载上限**：一次采集只占一个 SSH exec；应用每 60 秒最多启动一次，执行中拒绝排队。远端需要 GNU coreutils 的 `timeout`/`gtimeout` 和 `nice`：3 秒后终止，1 秒后强制结束采集进程组，`nice -n 19` 降低优先级、`ulimit -t 1` 限制每个采集进程的 CPU 时间。客户端 5 秒截止、512 KiB 输出上限。缺少限制工具则不执行采集。限制只作用于采集子进程，不修改服务进程。

---

## 2. 数据流

```text
已打开的 A SSH 会话
  -> 读取 A 本机 /proc socket 表
  -> 返回 A 的本机连接证据

已打开的 B SSH 会话
  -> 读取 B 本机 /proc socket 表
  -> 返回 B 的本机连接证据

NexTerm 本地归并
  -> 只比较已经返回的证据
  -> 生成服务器边 / 端口边
```

A 不访问 B，B 不访问 A，NexTerm 也不访问 A/B 的业务端口。通过跳板机打开的 SSH 会话沿用用户已有的管理通道；拓扑功能不会在该通道上创建额外转发。

---

## 3. Linux socket 采集

主数据源：

```text
/proc/net/tcp
/proc/net/tcp6
/proc/net/udp
/proc/net/udp6
```

采集规则：

- 不依赖 `ss`、`netstat`、`conntrack` 或 `nc`。
- 每张 socket 表最多 512 条记录（另有一行表头），接口最多 128 行；读取到下一行即停止并显式标记部分结果。反复采样不保证覆盖始终位于截断位置之后的记录。
- TCP 保留 `ESTABLISHED`、`SYN_SENT`、`SYN_RECV`、`FIN_WAIT*`、`CLOSE_WAIT`、`LAST_ACK`、`CLOSING`、`TIME_WAIT`。
- `TIME_WAIT` / closing 状态生成 observed 关系，不冒充当前活跃连接。
- UDP 只有远端地址和端口非零才生成关系；未连接 UDP 作为本地绑定端口，已连接 UDP 客户端端口不生成监听节点。
- 禁止遍历 `/proc/<pid>/fd`、批量读取进程 stat、全量 `ss`/`netstat` 快照或导出防火墙规则。旧解析器保留兼容历史输入，但采集脚本不再调用这些来源。
- 达到时间或输出预算后只保留完整分段，失败和部分采集不删除旧拓扑证据。进程归属与防火墙查询明确跳过，不能通过 IPC 参数重新启用。

进程信息缺失时：

- 服务器级边仍保留。
- 入站端口边仍指向当前真实监听端口。
- 出站边不能归属到本机某个真实监听端口时，绘制服务器级边，不创建临时端口。

BSD/macOS 没有当前支持的限量 socket 来源，因此跳过连接采集，不回退为全量 `netstat`。若缺少运行限时工具，整次采集跳过。已有拓扑仍可查看。

## 4. 地址与方向归并

### 4.1 地址归属

地址索引来自：

1. 服务器接口地址。
2. 节点主 IP。
3. 历史观测 IP。
4. 用户手工关系。

规则：

- IPv4-mapped IPv6（如 `::ffff:172.21.0.2`）会归一化为 IPv4，保证 Docker/双栈两侧能匹配。
- 地址唯一属于已保存服务器时生成到该服务器的边。
- 地址未知时生成 `observed:<ip>` 展示节点；该节点没有 connection id、没有端口表、不会被探测。
- 地址归属冲突时不猜测具体服务器，保留 observed endpoint。

### 4.2 方向

按本机 socket 形态判断：

1. 本地地址/端口命中真实 listener：远端服务器 → 当前监听端口。
2. 本地是客户端 socket 且能通过 PID/进程名唯一映射到本机 listener：本机服务端口 → 对端。
3. 无法唯一映射时：当前服务器 → 对端服务器/端口，不显示临时端口。
4. 状态不是活跃 socket 状态时标记 observed 而不是 active。

## 5. 端口模型

界面中只有真实监听端口节点：

```text
server_id
+ protocol
+ bind_address
+ port
```

不得合并：

- `127.0.0.1:5432`
- `0.0.0.0:5432`
- `:::5432`
- 不同网络命名空间的同号端口

客户端临时端口只存在于内部五元组，用于方向、去重和双端匹配；不得出现在图节点、表格、详情、筛选或手工编辑器中。

未知服务器的远端 `IP:port` 可以作为边上的观测证据显示，但不会生成该服务器的端口记录或端口节点。只有用户之后显式采集该服务器并且 `/proc` 中存在真实 listener，才回填真实端口 ID。

手工端口关系只能选择：

1. 真实监听端口 → 真实监听端口；或
2. 真实监听端口 → 服务器节点；或
3. 服务器节点 → 真实监听端口。

没有自由输入端口号，也没有虚拟端口。

## 6. 防火墙语义

低开销策略不再读取防火墙，仅保留已有元数据与人工备注，不刷新其采集时间。以下是历史数据的展示语义，不参与拓扑边或可达性判断：

```text
not_applicable       无活跃防火墙
metadata_available   活跃防火墙，规则/策略可读
unknown              权限不足或后端不可识别
```

无防火墙时显示「不适用」，不能显示为「允许」。监听、防火墙策略和实际连接分别展示，互不等价。

---

## 7. 持久化与合并

`net_*` 表继续通过显式行映射访问，不整行覆盖。

自动字段：

- 节点主机名 / OS / 主 IP / 角色提示。
- 接口、路由、防火墙、监听端口。
- 服务器边与端口边的自动状态和证据。

人工字段：

- 显示名、类型、环境、备注、标签、隐藏、布局坐标。
- 端口服务名、用途、备注、标签。
- 连线说明、标签、隐藏状态。

消失的监听端口不删除，标记 `missingSince`；已见过的自动关系保留为 observed/stale，不因一次采样缺失而立即丢失。

---

## 8. 验收清单

1. 点击采集前没有任何网络拓扑 IPC。
2. 采集脚本包含 `/proc` 与本机只读命令，不包含 `nc`、`/dev/tcp`、ping、DNS、traceroute 或远端连接 API。
3. observed IP 有服务器节点和边，没有端口表。
4. 客户端临时端口不在 UI 出现。
5. A/B 双端 `/proc` 证据能归并为同一条关系。
6. 进程信息缺失时服务器级边不消失。
7. `TIME_WAIT` 显示为 observed/recent 而不是 active。
8. 手工端口编辑器没有自由端口输入。
9. 无防火墙显示「不适用」。
10. `pnpm build`、`pnpm test`、`pnpm i18n:check`、`pnpm lint`、`cargo test` 与网络拓扑桌面 E2E 通过。


## 9. 累积拓扑与证据边界

- 每个已保存 SSH 连接有独立资产身份，不能仅因 IP 相同覆盖另一个连接。地址归属冲突保留观测端点，不猜测具体资产；文件夹只用于展示分组。
- 私网、VPN/CGNAT 与 IPv6 ULA 地址可标识真实服务器，不能用地址段黑名单认定它们都是容器。
- 只从当前服务器的本机 socket 表记录对端地址；未知入站和出站地址均可形成观测节点。节点出现、打开详情或切换页面都不会触发网络操作。
- 主机名使用 `uname -n`，不使用可能调用 DNS/NSS 的 `hostname -f`。操作系统分支在同一次脚本执行中通过 `uname -s` 选择，不另行探测工具。
- 仅采集主机元数据、限量接口和限量 Linux socket 表；跳过进程遍历、防火墙查询和 BSD/macOS 全量 socket 快照。
- 后续明确采集一个观测端点时，升级其节点并回填真实监听端口；归并不刷新旧连接证据的时间。双端采集的先后顺序不应产生重复连线。
- 服务归因与原始 socket 状态共同参与归并；一个 ESTABLISHED 连接不能掩盖其他 TIME_WAIT/closing 证据。
- 失败/不可用分段保留最近成功快照；部分分段可增加证据，但不能据此认定旧行已经消失。只有完整采集才能标记缺失。
- 完整采集中未再次看到的自动活跃关系保留为历史观测，人工关系与备注保留。历史观测不能当作实时连通性证明。
- 一次采集的本地写入使用 SQLite 事务；提交完成后才发布缓存和成功提示。失败不会发布半份拓扑，用户可手动重试。
- 采集提交期间的人工编辑按实际变化字段合并，保留新的自动采集字段；写入队列确保数据库和缓存一致。多个观测 IP 归属同一服务器时，按关系自然键合并并保留双方备注，避免唯一键冲突。

这里的“逐步完整”指不断合并**被采集到的主机与连接证据**，不代表主动发现全部物理网络设备。没有出现过、采样间隔内消失、权限或命名空间不可见的连接，以及 NAT 后无法唯一归属的地址，都不能保证自动还原。必须保留这类不确定性，不补造关系、不以访问其他服务器来验证。

### 验收范围与后续计划

- 已覆盖：双端采集顺序、重复采集、多跳证据累积、私网/IPv6、地址冲突、部分结果保留、事务失败及并发备注编辑。桌面测试使用独立本地数据库，验证拓扑查看与编辑不触发探测命令。
- 部署前验收：在用户授权的测试服务器上分别验证 Linux/macOS/BSD、普通用户与受限 `/proc` 权限，以及大连接表下的超时和截断。测试仍只读取被选中服务器，不向观测到的对端发送验证流量。
- 持续完善：展示采集覆盖范围与未知原因，结合后续手动采集补齐证据；不得把历史连接、未知地址或采集缺失展示为已确认的实时网络结构。

### 低开销策略的边界

本策略优先保护业务负载，接受拓扑覆盖率下降。只读操作、SSH exec 和内核表读取仍会消耗资源；CPU 时间限制不是固定 CPU 百分比限制，也不能承诺任何机器上绝对零影响。多个独立 NexTerm 实例各有自己的限频状态，不能作为服务器端全局配额。若要求服务器绝对零新增开销，只能停止实时采集，查看或导入已经存在的拓扑数据。
