# NexTerm 项目规划

## 产品方向

- **定位**：桌面端多协议连接工作区，一站式管理 SSH/SFTP/数据库/文档/API 调试
- **用户**：开发/运维人员，需要同时管理多台服务器与数据库的日常操作
- **差异化**：数据库工具箱与 SSH 隧道深度集成（PG/MySQL/SQLite 一键隧道连接）、真实终端体验、VS Code 式布局
- **安全基线**：敏感凭据加密存储、SSH host-key 强制 pin（数据库隧道 fail-closed）、压缩冗余特性移除

## 决策记录
- **幽灵列**：connections 表历史 `compression` 列有意保留，不做破坏性迁移（无代码读写），发布说明注明
- **zlib 移除范围**：SSH/SFTP/跳板/PostgreSQL 隧道全路径 `compression: NONE`（含 probe 连接）
- **PG 隧道安全模型**：fail-closed（服务端强制 pin），不依赖前端；SSH/SFTP 直连保持 TOFU 过渡（弹窗补偿）
- **`host_key_verification` 收敛评估（2026-08-28）**：审计确认前端所有 SSH/SFTP 连接路径（`buildSshConnectRequest`/`buildSftpConnectRequest`，src/lib/ssh-connect-request.ts）**从不发送** `host_key_verification` 字段；后端 `ConnectRequest`/`SftpConfig` 均带 `#[serde(default = "default_host_key_verification")]`（默认 `true`）。因此连接路径**恒为验证启用（fail-closed）**，settings 开关仅写本地偏好、不影响连接行为。结论：**不改后端**（保留字段作防御纵深 + 未来能力，移除需同步改 SshConfig/ssh/mod.rs/sftp_client.rs 及大量测试，风险大于收益）；暴露面收敛以"前端警示（P1）+ 本决策记录"完成。若未来某连接路径需显式传 false，须先评审并经双人确认。
