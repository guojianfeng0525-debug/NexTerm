# 网络探测持续排查与代码整理计划

日期：2026-09-22。基线：`eea5b98`（2.19.1）。范围：网络采集、证据归并、本地持久化及对应界面；不修改无关协议模块。

## 1. 必须保持的约束

- 只由用户手动触发，只读当前 SSH 服务器；不扫描、不解析对端 DNS、不连接观测到的服务器。
- 保持低开销预算：同一 SSH 端点最多一分钟一次、同端点无并发和积压任务；远端运行限制不可用则跳过；不恢复进程遍历、防火墙导出或全量 socket 命令。
- 部分/失败采集不能证明旧数据消失；地址归属、监听绑定、连接方向有歧义时不猜测。
- 人工字段、历史证据和已有数据库兼容性优先；不通过删除用户数据解决归并问题。
- 本轮使用模拟数据、本机测试服务和独立临时数据库，不对业务服务器做负载测试。
- 不承诺绝对零开销、零 bug 或还原从未观测到的完整物理网络。

## 2. 当前结构与整理目标

| 模块 | 当前职责 | 要解决的结构问题 |
| --- | --- | --- |
| `src-tauri/src/commands.rs` | IPC 与限频 | 预算常量散落，入口与策略耦合 |
| `src-tauri/src/os_detect.rs` | 平台命令生成 | 旧高开销命令与实际低开销路径混杂，注释容易失真 |
| `src-tauri/src/network_probe.rs` | 脚本包装、解析、归因 | 解析体量大；避免继续加入无关编排和重复策略 |
| `src-tauri/src/ssh/mod.rs` | SSH 通道与输出边界 | 运行预算与命令脚本需要保持一致 |
| `src/lib/network/topology-api.ts` | 探测结果应用与持久化编排 | 证据筛选、状态老化等策略内嵌，容易重复 |
| `src/lib/network/topology-merge.ts` | 纯数据归并与关联 | 必须统一绑定地址匹配和歧义处理 |
| `src/lib/network/topology-storage.ts` | 映射、缓存、写队列、恢复 | 提交中编辑/删除与重载交错复杂，应共享纯函数而不是堆补丁 |

整理原则：按真实职责提取小模块；公共入口保持兼容；只抽取有重复或独立测试价值的逻辑；不为文件行数机械拆分；不增加通用框架、依赖或第二套状态系统。

## 3. 执行阶段

### A. P0：持久化竞态复现与修复

1. 检查首次提交、并发人工编辑、节点删除、补偿写失败、数据库恢复读取的时序。
2. 用可控 Promise 暂停数据库读取/写入，复现恢复过程中新增、编辑、删除被旧快照覆盖的问题。
3. 将“数据库快照 + 并发本地变化”的合并提取成无 I/O 的函数；探测提交和恢复共用，避免两套相似代码。
4. 验证后续写入队列不会因一次失败永久阻塞；恢复失败不能吞掉原始失败原因。
5. 不新增数据库 schema，不引入远程读写。

验收：失败可见；恢复期间的用户操作保留；重载后的持久化状态与最终界面一致；重复提交不产生孤立关系。

### B. P1：监听绑定与证据归并

1. 排查相同协议/端口在不同网卡、IPv4/IPv6、通配地址和历史监听上的匹配。
2. 为“多个候选绑定”“已消失监听”“先观测后关联”的情况增加反例。
3. 提取唯一的监听解析函数，按地址证据筛选；不唯一时保留服务器关系和未解析端口 ID。
4. 检查解析身份不能刷新连接发生时间，部分采样不能重新产生被后端抑制的方向推断。
5. 复查接口过滤、节点升级及双端先后顺序的现有回归。

验收：不能把连线关联到错误网卡上的同号端口；历史数据不冒充当前监听；双端多次采样不增加重复关系。

### C. P2：预算统一与无效代码清理

1. 将冷却时间、远端时限、强制终止等待、CPU 时间、输出大小、行数上限集中定义。
2. SSH 执行器、命令生成器和入口限流引用同一策略，防止后续只修改一侧。
3. 全仓检索旧探测命令构造函数的调用者。只删除生产代码无调用的高开销构造函数及专属失效测试；保留仍有兼容价值的历史数据解析器。
4. 清理与实际行为不符的 TTL、防火墙、进程遍历、BSD 全量 fallback 注释。
5. 将本轮新增/修改的函数格式整理清楚，不对无关大文件执行整文件格式化。

验收：生产脚本仍无主动访问和高开销 fallback；预算定义只有一个来源；相关 shell 语法和边界测试通过。

### D. 回归、记录与交付

1. 每个确认 bug 先记录触发条件，尽可能先运行失败测试再修复。
2. 先跑相关网络测试，再统一运行前端测试、Rust 单元测试、构建、lint、i18n 检查和 diff 检查。
3. 只有影响桌面交互流程时才增加相应桌面验收；不重复运行无新增覆盖的测试。
4. 将实际修改、测试结果、未完成项和后续验收写回本文件；更新设计文档的结构说明。

验收：新增测试全部通过，编译无错误，新增代码无 lint 错误；不能把忽略或未执行的测试计为通过。

## 4. 不在本轮盲目扩大的工作

- 不整体重写所有网络 UI，不把历史解析器拆成大量仅有几个函数的文件。
- 不实现自动轮询、后台持续探测或跨实例服务器配额。
- 不新增扫描手段来弥补限量采样的覆盖不足。
- 不进行真实业务服务器上的兼容性、压力或长时间采样测试；后续需要明确测试对象与授权范围。

### 已确认的问题与处理方式

| 问题 | 触发条件 | 处理方式与回归 |
| --- | --- | --- |
| 读取失败被当作空拓扑 | 共用 `rowList` 在错误时返回空数组 | 拓扑恢复改用会抛错的读取入口；读取失败不发布快照、不清空已有节点和端口 |
| 数据库恢复覆盖用户操作 | `row_list` 返回前发生编辑、删除或新增 | 使用旧快照、数据库快照、当前缓存三方合并；三个可控读取竞态测试 |
| 同号端口关联错误网卡 | 目标服务器只有一个同号监听，但监听绑定的是另一个地址 | 选择器必须使用连接中的目标 IP，不能只比较端口号 |
| IPv6 对端错绑 IPv4 通配监听 | 目标为 IPv6，候选为 `0.0.0.0` | 区分地址族；IPv4-mapped 本地 socket 单独保留双栈证据 |
| 未解析目标在下次采集时错绑 | 已找到服务器，但还未找到对应监听，提前清空 `targetIp` | 保留 IP，直到监听确定；不同未解析目标地址分别计入关系身份 |
| 地址归属冲突后退回端口号猜测 | 已有关联服务器，但保留的目标 IP 无法唯一归属 | 有明确 IP 证据时禁止退回无地址匹配；继续保留未解析关系 |
| 无变化却增加解析计数 | 已知来源服务器、来源端口为空且为服务器级关系 | 没有身份变化时不写时间戳、不增加 resolved 数量 |
| 提交错误被恢复错误遮盖 | 补偿提交失败后，恢复读取再次失败 | 继续报告原始提交失败，并记录恢复错误；不伪造成功 |

### 结构整理结果

- `src-tauri/src/network_probe/policy.rs`：唯一预算来源和远端运行限制包装；预算数值不变。
- `src/lib/network/topology-listeners.ts`：唯一监听绑定匹配和选择实现；证据筛选、首次归并、后续解析共用。
- `src/lib/network/topology-reconcile.ts`：无 I/O 的三方行合并；缓存发布与数据库恢复共用。
- 删除 `routes_probe_cmd`、`ports_probe_cmd`、`peers_probe_cmd`、`fdmap_probe_cmd`、`firewall_probe_cmd`、`firewall_rules_probe_cmd`。全仓调用检索确认只有三个旧单测调用，无生产调用。旧数据解析器继续保留。
- 不新增依赖、数据库迁移、定时任务或网络请求；不修改业务服务器配置。
